# Deployment Guide — Streamlit Community Cloud

Local execution is **mandatory** and already works without the cloud. Public
deployment is optional.

## Prerequisites

- A GitHub account and a public (or connected private) repository containing this project
- Streamlit Community Cloud account: https://share.streamlit.io/
- Committed files: `streamlit_app.py`, `pages/`, `streamlit_lib/`, `backend/app/`,
  root `requirements.txt`, `data/lexicons/`, and `.streamlit/config.toml`

## Steps

1. Push this project to GitHub (only when you choose to — do not publish private data).
2. Open Streamlit Community Cloud → **New app**.
3. Select the repository, branch, and **Main file path**: `streamlit_app.py`.
4. Confirm Python version compatible with `requirements.txt` (3.11–3.14 recommended).
5. Deploy and wait for the build log to finish.

## Paths

All paths resolve from the repository root via `backend/app/core/config.py`
(`ROOT_DIR` / `BACKEND_DIR`). Do not hardcode absolute Windows paths in cloud config.

SQLite will be created under `backend/data/app.db` on first run. On Streamlit Cloud,
ephemeral disks can be wiped when the app sleeps or redeploys — export important
reports under `artifacts/exports/` and keep local backups of research data you care about.

## Artifacts

| Artifact | Cloud note |
|----------|------------|
| `backend/data/app.db` | Created at runtime; may not persist across sleeps/redeploys |
| `artifacts/models/` | Prefer committing small trained joblib artifacts if you want instant models |
| `artifacts/exports/` | Generated by Research Center export; download after generate |
| `data/lexicons/` | Required for dictionary baseline |
| Large Daraz / private CSVs | **Do not** upload unless redistribution is allowed |

Training on Streamlit Cloud free tier is possible but slow/limited. Prefer training
locally, then commit small model artifacts if needed for demo inference.

## Keep-alive (optional)

Free Streamlit apps can hibernate after ~12 hours without traffic.

This repo includes:

`.github/workflows/streamlit-keepalive.yml`

It pings the app every **8 hours (UTC)** so an already-awake app is less likely to sleep.

### Setup after you have a live URL

1. Edit `APP_URL` in the workflow to your real URL, **or**
2. Add a GitHub Actions variable `STREAMLIT_APP_URL` (recommended).
3. Push to GitHub and ensure Actions are enabled.
4. Run **Actions → Streamlit keep-alive → Run workflow** once to test.

### Important limits

- Keep-alive helps an **already awake** app stay active.
- It does **not** reliably wake a sleeping app.
- If the app is asleep, open the URL in a browser and click
  **“Yes, get this app back up!”**
- Do not use bare `curl -L` without a cookie jar (Streamlit can redirect-loop).

## What not to do

- No paid APIs, secrets, or GPU services for the core path
- No scraping at runtime
- Do not claim a live demo URL until you open it and verify Analyzer + Datasets work
